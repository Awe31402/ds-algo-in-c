# 31 · B-Tree

## 一句話
**B-Tree** 是一種**又寬又矮**的平衡搜尋樹：每個節點可以放**很多個 key**、有很多個小孩。它是為**磁碟**設計的：讀一次磁碟就讀進一整個節點（例如 4 KB），所以樹越矮，讀磁碟的次數就越少。資料庫索引、檔案系統幾乎都用它（或它的變形 B+ Tree）。

## 定義（CLRS 18.1），最小度數 t ≥ 2
1. 每個節點最多 **2t − 1** 個 key、**2t** 個小孩。
2. 除了根，每個節點至少 **t − 1** 個 key（根至少 1 個，除非整棵樹是空的）。
3. 節點裡的 key 由小到大排；有 n 個 key 的內部節點剛好有 n + 1 個小孩，key 是小孩之間的分隔：
   ```
            [ 20 | 40 ]
           /     |     \
     (< 20)  (20~40)  (> 40)
   ```
4. **所有葉子都在同一層。**

t = 2 時，每個節點有 2～4 個小孩，就是 **2-3-4 樹**（紅黑樹就是它的另一種寫法，見第 18 主題）。

### 高度（CLRS Theorem 18.1）
n 個 key 的 B-Tree，高度 h ≤ log_t((n + 1) / 2)。
例如 t = 1001、n = 10 億：高度只有 **2**，找任何一個 key 最多讀 3 次磁碟。

## 插入：往下走的時候，遇到滿的節點就先分裂（CLRS 18.2）
新的 key 一定插在**葉子**。如果先走到葉子才發現滿了，分裂之後父節點也可能是滿的，要一路往回處理。
CLRS 的做法是**一路往下走的時候，遇到滿的節點就先分裂**，保證父節點一定有空位，一趟就能插完。
```
分裂 (split)，t = 3：
       [ 30 ]                         [ 30 | 60 ]
         |                            /    |    \
  [40 50 60 70 80]    →      ...  [40 50]    [70 80]
      （滿了，5 個）                 中間的 60 升到父節點
```
**根滿了就分裂根，長出新的根**：B-Tree 只會從上面長高，所以葉子永遠在同一層。

## 刪除：往下走之前，先確保下一層至少有 t 個 key（CLRS 18.3）
| 情況 | 狀況 | 做法 |
|---|---|---|
| 1 | key 在葉子 | 直接刪 |
| 2a | key 在內部節點，左小孩 ≥ t 個 | 用**前驅**取代它，再到左小孩刪前驅 |
| 2b | 右小孩 ≥ t 個 | 用**後繼**取代，再到右小孩刪後繼 |
| 2c | 左右都只有 t − 1 個 | 把 key 和右小孩**合併**進左小孩（變成 2t − 1 個），再往下刪 |
| 3a | key 不在這個節點，要走的小孩只有 t − 1 個，但**兄弟有 ≥ t 個** | 透過父節點**向兄弟借一個**（旋轉） |
| 3b | 兄弟也都只有 t − 1 個 | 跟兄弟**合併**（父節點下來一個 key 當中間） |

```
3a 向右兄弟借（t = 2）：
      [ 20 ]                     [ 30 ]
     /      \        →          /      \
  [10]    [30 40]           [10 20]   [40]
（左邊只剩 1 個，右兄弟有 2 個：父節點的 20 下來、右兄弟的 30 上去）
```
如果根的 key 被合併光了，根就換成它唯一的小孩，**樹變矮一層**。

## 複雜度
n 個 key、最小度數 t：
| 操作 | CPU 時間 | 讀寫磁碟次數 |
|---|---|---|
| 搜尋 | O(t log_t n) | O(log_t n) |
| 插入 | O(t log_t n) | O(log_t n) |
| 刪除 | O(t log_t n) | O(log_t n) |

## B-Tree vs B+ Tree（Thareja 11.3、16.7.6）
| | B-Tree | B+ Tree |
|---|---|---|
| 資料放哪 | 每個節點都放 | **只放在葉子**，內部節點只放索引 |
| 葉子 | 互相獨立 | **串成串列**，範圍查詢很快 |
| 用途 | 一般 | 資料庫索引（MySQL InnoDB）、檔案系統 |

## 面試陷阱／常考點
1. **為什麼資料庫用 B-Tree 而不是紅黑樹？** 磁碟讀取以「塊」為單位，一次讀進很多 key 最划算。B-Tree 很矮，讀磁碟的次數少；紅黑樹是二元樹，太高了。
2. **B-Tree 從根長高**，不是從葉子長，所以所有葉子永遠在同一層。
3. **主動分裂／主動補足**（CLRS 的一趟式寫法）：往下走之前先處理好，就不用再往回走。
4. **刪除比插入複雜得多**：要記得三種情況和子情況。
5. **t 是「最小度數」**：有些書用「階 (order) m」表示「最多 m 個小孩」，m = 2t。看題目時要注意定義。
6. **2-3-4 樹 ↔ 紅黑樹**：一個黑節點加上它的紅小孩，就是一個 B-Tree 節點。
