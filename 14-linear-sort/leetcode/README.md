## 1365 · How Many Numbers Are Smaller Than the Current Number（Easy）
[題目](https://leetcode.com/problems/how-many-numbers-are-smaller-than-the-current-number/) · [程式](1365-how-many-numbers-are-smaller-than-the-current-number.c)

**題意**：對每個 `nums[i]`，算陣列裡有幾個數比它小。值的範圍是 0..100。

**思路**：就是計數排序的前兩步。
1. 數每個值出現幾次。
2. 做前綴和，就知道「比 v 小的有幾個」。

本檔的小技巧：把 v 的次數存在 `cnt[v + 1]`，做完前綴和之後，`cnt[v]` 剛好是「< v」的個數，不用再減掉自己。

**複雜度**：O(n + 101)。暴力解是 O(n²)，排序解是 O(n log n)。

## 1051 · Height Checker（Easy）
[題目](https://leetcode.com/problems/height-checker/) · [程式](1051-height-checker.c)

**題意**：大家應該依身高由矮到高排隊。有幾個人站錯位置？

**思路**：用計數排序得到「應該的順序」，再逐格比較。
身高只有 1..100，所以不用真的產生排好的陣列：從 `cnt` 裡依序取出「下一個應該出現的身高」，邊走邊比。

**複雜度**：O(n + 100)。

**陷阱**：問的是「位置不對的人數」，不是「最少要換幾次」。後者要用環 (cycle) 的想法來算。

## 274 · H-Index（Medium）
[題目](https://leetcode.com/problems/h-index/) · [程式](0274-h-index.c)

**題意**：h-index 是最大的 h，使得「至少有 h 篇論文，每篇都被引用至少 h 次」。

**思路**：h 不可能超過論文數 n，所以引用數 > n 的都當作 n。
1. `cnt[c]` = 引用數為 c 的論文數（c > n 的都算進 `cnt[n]`）。
2. 從 h = n 往下，累加「引用 ≥ h 的論文數」。
3. 第一個讓「論文數 ≥ h」成立的 h，就是答案。
```
citations = [3 0 6 1 5], n = 5
cnt = [1 1 0 1 0 2]      (6 被截成 5)
h=5: 累計 2 篇 < 5
h=4: 累計 2 篇 < 4
h=3: 累計 3 篇 ≥ 3 → 答案 3
```

**複雜度**：O(n)。排序解是 O(n log n)：排序後找第一個 `citations[i] >= n - i` 的位置。

**陷阱**：引用數可能到 1000，但 n 可能很小，所以一定要截斷在 n，否則計數陣列會越界。

## 164 · Maximum Gap（Medium）
[題目](https://leetcode.com/problems/maximum-gap/) · [程式](0164-maximum-gap.c)

**題意**：排序後相鄰兩個數的最大差距是多少？要求線性時間。

**思路：桶子 + 鴿籠原理**
- n 個數分布在 [lo, hi]，中間有 n − 1 個間距，總長是 hi − lo。
- 所以**最大間距 ≥ 平均間距** = (hi − lo) / (n − 1)。
- 把桶寬設成平均間距（至少 1）：同一個桶裡兩個數的差 < 桶寬 ≤ 最大間距。
- 所以最大間距**一定出現在不同的桶之間**：某個非空桶的最小值 − 前一個非空桶的最大值。
- 每個桶只要記 min 和 max，完全不用排序。

```
[1 3 6 9], lo=1, hi=9, 桶寬 = 8/3 = 2
桶 0 [1,3): 1     桶 1 [3,5): 3     桶 2 [5,7): 6     桶 3 [7,9): 空     桶 4 [9,..): 9
間距：3-1=2, 6-3=3, 9-6=3 → 答案 3
```

**複雜度**：O(n) 時間、O(n) 空間。也可以用基數排序，同樣是線性時間。

**陷阱**：
- 桶寬至少要是 1，否則所有數都相同或很密的時候會除以 0。
- `hi - lo` 可能超過 int（例如 0 和 10⁹ 還好，但一般情況要小心），本檔用 `long long` 計算。
- 空桶要跳過，但「前一個非空桶的最大值」要一直往後帶。
